Method

Scenario A is the existing Dashuri six-month model (docs/finance/engine/dashuri-model.js, unchanged). Scenario B runs the same engine with five Reels levers applied to its inputs: payer churn, non-payer retention, later conversion, organic sign-ups and (as a risk) calls per payer. Incremental results are B − A, so the calls existing customers would have made anyway are never credited to Reels.

Reels costs are added to B only: Mux storage (all uploaded minutes, including rejected media kept 90 days as evidence), Mux delivery beyond 100,000 free minutes, basic encoding (free), the $20 pay-as-you-go credit, Sightengine operations on top of the call-moderation operations already on the same plan (frames every N seconds × models), human review, extra API/DB load, appeals/copyright support and a one-time legal review.

Definitions. Incremental contribution = Δ engine contribution − Reels variable costs. Incremental operating = Δ engine operating profit − all Reels costs. Cost per 1,000 views uses variable costs. Break-even views = fixed Reels costs ÷ (incremental value per view − variable cost per view). Extra cash = the deepest point of cumulative (B − A) net cash flow.

Limits. There is no Reels usage data. Every impact input is an assumption, so treat the outputs as "what would need to be true". Host liabilities rise with extra paid minutes (Beans owed, payouts are off).
